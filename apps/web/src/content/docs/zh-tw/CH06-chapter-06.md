# 故事、情節與因果結構

> 編輯狀態：研究草稿；英文為工作譯稿。理論頁碼、電影觀片定位與雙語校譯仍待人工審查。本文的流程表、提示詞和案例練習屬本書的實務示範，不是經驗研究結論。

<a id="CH06-S01"></a>
## 學習目標
完成本章後，讀者能分辨故事材料與情節安排；以因果、人物目標、資訊揭露和觀眾推論拆解一段敘事；把場景寫成可拍攝的行動與後果；比較線性、倒敘、多視點及留白結構；並使用可追溯的結構化資料，讓 AI 協作但不把模型輸出當成已驗證的劇本。先備知識：CH01 的電影語言、CH02–CH03 的鏡頭與觀看位置、CH05 的類型與再現倫理。

<a id="CH06-S02"></a>
## 先備知識
本章不要求讀者先接受三幕劇或任何單一商業公式。需要具備基本場景概念：人物在特定時間、空間和限制中採取行動；鏡頭與剪輯安排觀眾何時看見資訊。若使用既有作品作分析，請選擇合法取得版本，記錄版次、字幕／配音版本及可重現時間碼；本章不提供未經親自觀片的逐鏡時間碼。

## 核心術語
| ID | 繁體中文 | English | 本章操作性定義 |
|---|---|---|---|
| TERM-CH06-STORY | 故事 | story | 觀眾依作品線索推論出的事件、人物與世界之整體時間關係；此處作為工作定義。 |
| TERM-CH06-PLOT | 情節 | plot | 作品實際選擇、排序、延遲或重複呈現的事件。 |

| TERM-CH06-MOTIVATION | 動機 | motivation | 使人物選擇某項行動的目標、信念、需求或壓力。 |

上述中英詞條與定義為 CH06 工作詞彙，等待術語編輯核定。亞里斯多德對情節、完整行動、逆轉與發現的論述，取自其悲劇理論文本；本章將之轉化成分析提問，而非宣稱所有類型必須遵循同一規則 [R046]。

<a id="CH06-S04"></a>
## 歷史與基本原理
亞里斯多德《詩學》把悲劇情節（mythos）描述為事件的安排，討論完整行動、開端／中段／結尾、可能性或必然性、以及情勢逆轉和發現。這是古希臘悲劇論述的歷史材料，不是現代電影劇本的普遍法則；中譯詞也會隨譯本不同 [R046]。Bordwell 在〈電影敘事的三個面向〉中區分推論出的故事（fabula）與作品中的情節安排（syuzhet），並指出敘述也涉及視聽風格；此處依作者公開章節第 3 章「Narration and story」第 14–15 頁（PDF 第 13–14 頁）定位 [R051]。R047 則僅作《小說電影中的敘述》書目與研究範圍參考；本章不把未查閱該書全文的具體論點歸給它。

本章採用四個可操作問題：一、人物想做什麼？二、因何採取此行動？三、行動改變了什麼？四、觀眾知道、誤解或尚不知道什麼？把事件寫成「而且接著發生」容易得到流水帳；改問「因為／但是／所以」可測試因果鏈，但這是編輯診斷工具，不是保證戲劇效果的公式。偶然、沉默、停滯、非線性與開放結尾皆可能有意義，關鍵是作品是否能建立觀眾可感知的模式與期待。

<a id="CH06-S05"></a>
## 傳統製作方法
編劇通常從人物、處境、欲望、阻礙和選擇建立素材，再以大綱、節拍表、場景表及劇本反覆修訂。製片、導演、演員與剪輯師會檢視每場戲的拍攝可行性、人物行動、場景轉折、資訊揭露和前後連接。實務檢查不是要求每場都「推進主線」：場景也可以建立關係、氣氛、主題或觀眾預期，但需要知道它如何改變整體經驗。

建立因果鏈時，為每個節點記錄：前提、行動者、目標、選擇、阻力、結果、後續代價、觀眾掌握的資訊。若某事件刪除後，後續事件毫無變化，需判斷它是刻意的節奏／主題停頓，還是可合併的重複。倒敘與多視點則分別記錄「故事時間」和「呈現時間」，並比對每次重述新增、刪除或改變了什麼；不能把角色說法直接等同客觀真相。

<a id="CH06-S06"></a>
## AI 時代的技術轉換與限制
語言模型可以協助提出替代因果鏈、找出未交代的動機、整理場景資料及生成不同排序的草案；這些是可測的工作假設，不代表模型能判斷人物心理真實性、文化語境或藝術價值。模型可能把偶然改寫成刻意伏筆、補上原稿沒有的設定、混淆人物與版本，或產生表面合理但前後矛盾的事件。每輪輸出應保存提示詞、模型／版本（若可得）、日期、輸入稿雜湊、採用與拒絕的建議及人工修改。

採「人類持有故事真相表，模型只在授權邊界內提案」：先提供明確人物、世界規則、不可變事實與禁止新增事項；每項 AI 建議必須指出原稿證據或標為推測；作者決定是否採納。不得把未獲授權的劇本、演員私密資料或第三方受保護文本輸入外部服務；資料保留、訓練使用及商業權利依工具當時官方條款與專案合約另查，不能從訂閱方案推定。


<a id="CH06-S07"></a>
## 逐步工作流程
1. **寫一句核心行動**：主角在何種限制下追求什麼可觀察目標？
2. **列出故事事實**：區分已定稿事實、人物信念、觀眾已知與作者尚未決定事項。
3. **建立因果節點**：每節點記錄觸發條件、行動、阻力、結果及造成的下一個問題。
4. **測試人物能動性**：角色是否做出選擇；若只被事件推著走，這是否為設計？
5. **設計資訊順序**：決定哪些先展示、延後、重複或由不同人物講述；標出每次新增資訊。
6. **建立場景目標**：每場列入場狀態、人物目標、策略、變化、出場狀態及可拍攝行動。
7. **檢查因果與偶然**：以「因為／所以／但是」摘要；找出只有時間相鄰、沒有因果支持的事件。若需保留偶然，記錄其主題或形式目的。
8. **讓 AI 做有限診斷**：要求列出疑點與證據位置，不要求自動改寫整部作品。
9. **作者決策與版本差異**：接受／拒絕每項建議，更新 story bible、版本號和變更紀錄。
10. **桌讀與剪輯式驗證**：朗讀場景，檢查目標能否理解、資訊是否公平、轉折是否可追溯；再以分場卡重排測試節奏。

## 提示詞與技術參數
以下為模型中立的教學範本，尚未對特定模型實測。先刪除機密與未授權資料，並以假想短片測試。輸出格式採 JSON，便於差異檢查；`evidence` 必須指向提供的 scene_id 或明確標示 `inference`。

```text
角色：你是劇本結構分析助理，不是共同作者或故事事實來源。
任務：只診斷我提供的場景鏈。不得新增人物、世界規則、道具或事件。
固定事實：{story_facts}
場景資料：{scenes}
請檢查：因果連接、動機依據、選擇與代價、資訊揭露順序、連續性矛盾。
每項發現回傳：scene_id、問題類型、原文證據（短摘或欄位）、影響、最多兩個修訂選項、推測標記。
沒有證據時回傳「無法判定」，不可補寫。
輸出：符合下列 JSON schema 的純 JSON，不要輸出劇本正文。
```

```json
{
  "schema_version": "1.0",
  "chapter_id": "CH06",
  "findings": [
    {
      "scene_id": "S03",
      "issue_type": "causal_gap",
      "evidence": "明確欄位或原文位置；若推測則填 inference",
      "impact": "對觀眾理解／人物選擇的可能影響",
      "options": ["修訂選項 A", "修訂選項 B"],

```

輸入／輸出都應保存 UTF-8、schema version、source revision、model/tool/version、run date。JSON 需經 parser 與 schema 驗證；若無法驗證工具版本，就記錄「未記錄」，不猜測。此處不指定 token、temperature 或供應商參數，因不同工具的語意、可用性與設定可能變動。

## 電影案例與觀察練習
《羅生門》（羅生門／Rashōmon, 1950）可作為多次講述與觀點差異的案例。Criterion 片目提供作品年代、規格、主創及多個人物對同一事件提出不同說法的概要；Stephen Prince 的評論進一步分析回憶段落與多重敘述。這些是片目與影評的二手資料，不是本書作者已完成觀片的證據 [R048, R049]。案例用途是提出分析問題，不把「羅生門效應」簡化成「每個人都在說謊」或宣稱只有一個謎底。

分析表至少分列推論的事件時間（fabula）與作品呈現順序（syuzhet）；這是閱讀工具，不應將兩者差異自行當成角色說謊的證據 [R051]。

觀片任務：選擇合法可取得的版本，在看片前建立事件表；對每次重述記錄講述者、可見／可聞證據、與前版本一致和不一致之處、觀眾此時知道什麼。記錄發行版、片長、字幕版本及時間碼；不要將不同剪輯版的時間碼混用。再選一項差異，判斷它改變的是事件、角色自我形象、觀眾信任，還是資訊來源。任何鏡頭細節須由作者實際看片後補入；本章目前沒有聲稱特定鏡頭時間碼。

另作自創微型練習：同一把遺失的鑰匙，由三名角色各自描述。每個版本只能改變角色所知、利益或觀察位置，不得無故更改固定事件；比較資訊差異如何重塑觀眾推論。不得照搬《羅生門》的角色、情節或視覺設計。

## 常見錯誤與品質檢查
- **把順序當因果**：用「因為／所以」改述；若只能說「然後」，補上中介行動或承認為偶然。
- **角色目標含糊**：改成鏡頭可觀察的行動，避免只寫「想要幸福／被理解」。
- **靠隱瞞作者資訊製造驚訝**：檢查先前場景是否公平提供線索；若故意不可靠，觀眾仍需理解不可靠的來源。
- **每段倒敘都重複相同內容**：要求每次重述帶來可辨識的新資訊或改變觀眾對既有材料的解讀。
- **把結構公式當法律**：比較類型、片長、文化形式與作者意圖；三幕、節拍表等是可用工具，不是成功保證。
- **AI 擅自補設定**：逐條比對 story bible，無來源內容標為模型提案，未經作者確認不得進入正稿。
- **把理論概念當作者原話**：引用前核對採用版次、譯本和 locator；分析句與來源事實分開標記。

品質驗收表：每個核心事件有 ID；主要行動者、目標、阻力和結果可辨識；因果、偶然及未知事項有標記；故事時間與呈現時間分開；倒敘版本差異有記錄；每個 AI 建議有證據／推測狀態及人工決策；場景重排不破壞固定事實；引用來源存在且 locator 不捏造。自動檢查可驗證 IDs、必填欄位、JSON、雙語對照與連結格式；人物可信度、情感力及藝術效果仍需人類評讀。

<a id="CH06-S11"></a>
## 練習、評量與延伸研究
**練習 A（因果圖）**：寫一頁、6–10 個節點的原創短片事件鏈，標示節點前提、人物選擇、結果和下一步。另寫一份只呈現資訊順序的情節表，兩表不得混為一談。

**練習 B（重述設計）**：設計同一事件的兩種講述版本，寫明講述者各自知道什麼、隱瞞什麼及可能誤記什麼；由同儕只根據影片資訊推論差異，不以作者口頭解釋補足。

**練習 C（AI 診斷）**：使用本章範本分析匿名化場景表；人工核對每個發現是否有原稿證據。評量（0–4）：因果可追溯、人物選擇具體、資訊差異可辨、AI 建議可追溯。此量表是課堂工作工具，非經驗效度研究。

延伸研究：不同文化敘事傳統中事件因果和結尾期待的差異；觀眾對不可靠敘述的推論；生成式模型長篇敘事中的跨場景一致性與人類編輯策略。研究設計需記錄語料、模型版次、測試條件及倫理／授權安排。
