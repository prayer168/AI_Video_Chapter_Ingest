# 引用、參考資料與外部連結規範

## 證據層級

1. **原始／官方資料**：電影本身、製作文件、典藏機構目錄、標準組織文件、工具官方文件與正式版本說明。
2. **專業研究**：學術專書、同儕審查論文、可信賴的電影研究機構出版物。
3. **專業實務出版**：具編輯責任的業界書籍、協會手冊、專業教育機構材料。
4. **其他資料**：新聞、訪談、社群文章等僅用於脈絡或線索；關鍵事實應另找一手或專業來源核實。

搜尋摘要、AI 回答、未署名貼文不可單獨支撐事實主張。影片平台上傳者不明時，不用於確認作品版本或日期。

## 文內引用

- 使用穩定來源 ID，例如 `[S001]`，來源完整資料維護在 `data/references.yaml`。
- 引用書籍時盡可能提供頁碼／章節；論文用 DOI 或期刊正式頁；影音用版本及時間碼；線上文件記錄標題、發布者、版本／更新日期、查閱日期與 URL。
- 直接引文須使用引號並附精確定位；遵守著作權合理引用範圍。一般敘述優先改寫並清楚標明來源。
- 對有爭議的理論主張提供不同觀點來源；不要將理論詮釋偽裝為可量測事實。
- 每筆線上來源記錄 `accessed` 日期。來源失效時保留書目、記錄失效狀況，並尋找合法存檔或替代正式來源。

## 建議來源資料欄位

`id`, `type`, `title`, `creator`, `publisher`, `publication_date`, `edition`, `version`, `doi`, `url`, `accessed`, `locator`, `language`, `notes`。未知欄位省略或填 `null`，不可推測補齊。電影作品另外記錄 `work_title`, `release_year`, `director`, `release_or_restoration_version`, `timecode`。

## 時效性與實測

AI 產品、模型、功能、價格與政策可能快速變動。每一項都要有官方來源及查閱日期；版本要能確認才寫入。實測記錄作業系統、工具／模型版本、日期、輸入條件、可分享的結果與限制。無法確認時明確標示「未確認」。

## 外部連結檢查

`python scripts/check_links.py` 掃描本地 Markdown 的 HTTP(S) 連結。使用 `--online` 才會發出網路請求；網路錯誤、逾時或拒絕連線只報告待人工確認，不得直接等同來源不存在。檢查結果不得替代人工來源品質審查。
